Record Label E-Commerce Platform

Architect & developer · Endnote Records · 2026

A production storefront, admin console, and in-person point-of-sale for an independent record label, with dual-currency pricing, idempotent order processing, content management, role-based admin access, and per-currency reporting.

A TypeScript monorepo built with Turborepo and pnpm workspaces: two Next.js 16 / React 19 applications over four shared internal packages, about 35K lines across 36 Postgres tables and 24 versioned migrations. Prices are set per currency instead of being converted, so USD and CAD are separate columns resolved through a three-level chain, and every subsystem that reads a price has to track which currency it came from.

  • Built currency switching with no layout shift that keeps Incremental Static Regeneration working. Both prices render server-side, and a pre-paint inline script plus CSS picks one, so product pages stay statically generated while each visitor sees their own currency.
  • Made Stripe Checkout idempotent end to end, with signature-verified webhooks, a reconciliation cron to catch lost events, and inventory reserved at session creation with automatic sweeping of abandoned checkouts.
  • Built a channel- and currency-aware analytics layer that never sums across currencies, uses a fixed default so figures do not change between page loads, and labels excluded orders instead of reporting a partial number as a total.
  • Shipped a mobile-first point-of-sale for live shows, covering cash and e-transfer sales, oversell-tolerant stock decrements through an inventory ledger, per-currency line re-pricing, and cost snapshots recorded in the sale's own currency to keep margin accurate.
  • Built role-based access control on better-auth with granular permission statements across three roles, checked on every admin route and server action, with an append-only audit log on all money, inventory, and user changes.
  • Secured the public endpoints with Zod validation before any database access, IP-keyed rate limiting on unauthenticated routes, honeypot bot filtering, parameterized queries, CSP headers, and generic client errors that keep detail server-side.
  • Set up the release workflow after a schema-lag outage. Migrations deploy before code, GitHub Actions applies them to Neon on merge, and a typecheck, lint, test, and build gate runs across all 16 workspace tasks.
